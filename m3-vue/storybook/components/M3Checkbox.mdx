# Checkboxes

Checkboxes let users select one or more options independently. They also support parent-child selection patterns where a parent reflects the aggregate state of subordinate items.

## API

### When to use

Use `M3Checkbox` when multiple items can be selected at the same time, or when a single option behaves like a boolean choice inside a form. If the user must pick exactly one option, prefer radios instead.

### Selection model

This implementation supports both simple boolean selection and array-backed multi-select models. It also supports `indeterminate` for aggregate parent rows, which matches the Material 3 guidance for nested selection patterns.

### Nested selection

In nested lists, the parent checkbox should summarize descendant state:

- checked when all descendants are selected
- indeterminate when some descendants are selected
- unchecked when none are selected

## Accessibility semantics

- Every checkbox needs a visible text label.
- Group related checkboxes under a shared group label (`fieldset/legend` or `aria-labelledby`).
- Use indeterminate state only for partial parent-selection states.

## Usage guidance

### Keep labels explicit

Checkbox labels should describe the resulting state, not the control itself. "Email receipts" is clearer than "Enable."

### Use indeterminate only as summary state

Do not present `indeterminate` as a user-selectable third state. It should only communicate partial selection across descendants.

# Флажки

Флажки позволяют независимо выбрать один или несколько вариантов. Они также поддерживают родительские состояния, отражающие совокупный выбор дочерних элементов.

## API

### Когда использовать

Используйте `M3Checkbox`, когда одновременно можно выбрать несколько элементов или когда один параметр работает как логическое значение формы. Если нужно выбрать ровно один вариант, используйте radio-кнопки.

### Модель выбора

Поддерживаются простое логическое значение, выбор нескольких значений через массив и `indeterminate` для агрегирующих родительских строк.

### Вложенный выбор

В иерархическом списке родительский флажок должен быть отмечен при выборе всех потомков, неопределённым при частичном выборе и снят, когда не выбран ни один потомок.

## Доступность

- У каждого флажка должна быть видимая подпись.
- Связанные флажки объединяйте общей подписью группы через `fieldset/legend` или `aria-labelledby`.
- Используйте неопределённое состояние только для частичного выбора потомков.

### Обычный список

## Рекомендации

### Явные подписи

Подпись должна описывать итоговое состояние, а не сам элемент управления. «Получать чеки по почте» понятнее, чем «Включить».

### Неопределённое состояние — только для сводки

Не предлагайте `indeterminate` как третье состояние, выбираемое пользователем. Оно сообщает лишь о частичном выборе потомков.
